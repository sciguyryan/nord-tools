# D3 real-reboot host protection acceptance

D3 runs only inside the disposable Arch Linux guest provisioned by `scripts/acceptance-manager.py`. It is part of the regular `test` action after D1 and D2 have returned their host to the original state. It is not an operator-host installation procedure and must not be run on a workstation.

The runner first uploads and verifies the source tree, completes the ordinary quality and privileged acceptance stages, and prepares four disposable systemd units. It then requests an actual libvirt guest reboot and checks that the kernel boot ID changes. The guest's early fixture unit creates an isolated WireGuard peer and a boot-specific, credential-free host plan. The production early-barrier unit must then install the deny barrier before `network-pre.target`, with the activation unit running after the barrier and `network-online.target`. The peer is available as a local network namespace, so the test does not depend on an external VPN provider.

The runner uses the guest's virtio serial QEMU guest agent for inspection while the deny barrier blocks SSH. This is intentional: neither the agent nor the operator's libvirt control channel relies on the guest's network route. The test requires an active QEMU guest agent and a working serial console. It rejects a mere service restart or a libvirt acknowledgement as evidence of a reboot. It verifies the actual boot ID, unit activation and monotonic start ordering, the production host executor's `active_verified` status, IPv4/IPv6 routes and real dual-stack DNS exchanges.

After confirming protected operation, the test kills a deactivation worker at the route-retirement checkpoint, verifies that the barrier remains installed, performs explicit ownership-aware recovery, and completes barrier-last retirement. It checks that the original nftables ruleset is restored and that the owned WireGuard interface and policy routing are absent. Finally, it disables the disposable boot units, removes the peer fixture and requires the normal SSH channel to return before recording the D3 result. The evidence remains under `/var/lib/nord-tools-d3` and `/var/tmp/nord-tools-d3-result.json` in the disposable guest.

A failed or uncertain host transition is **not** automatically undone. The guest may remain without SSH; use the libvirt serial console and the QEMU guest agent to inspect `systemctl status nord-tools-host-barrier.service nord-tools-host-activate.service`, `journalctl -b`, the D3 evidence directory and the host transaction store. Do not flush nftables, delete host routes or discard the store to make SSH work. For a disposable test VM, a clean rebuild is preferable to unsafe manual host networking changes.

This D3 stage tests one real reboot into a newly installed protected configuration and an interrupted transition followed by explicit recovery in that new boot. It does not certify automatic cross-boot recovery of an existing incomplete transaction, competing host managers, or physical-host deployment. Those cases remain outside this guest acceptance claim unless separately demonstrated. D3 should only be marked accepted after the complete privileged guest run succeeds.
